What it is

What it is

The engine

The model is the product

Rollover, overspend handling and credit-card payment envelopes are where budgeting apps either get it right or quietly fudge it. Both overspend models ship — reduce next month's Ready to Assign, or carry the negative — and switching re-derives every month since.

Money in

India is an ingestion problem

Rupee formatting is trivial. Reconstructing a ledger from UPI/P2M/…/SWIGGY, split card cycles and password-protected statement PDFs is the actual work. Nothing auto-posts: every imported row waits for a human, with its raw string kept.

Where it runs

One container, your box

Node's standard library covers everything — SQLite, HTTP, crypto, tests. Even the PDF reader and the statement decryption are written in-repo rather than pulled from npm. No telemetry, no third party, no account with anyone.

The invariant

Money cannot be created by a screen

Every envelope app has an accounting identity underneath it. Most leave it implicit, which is how a rounding error becomes a support ticket nobody can reproduce. Here it is written down, and asserted after every scenario in the test suite.

If a change breaks the identity, the change is wrong — including when the change looked like a bug fix. That has caught real errors: an uncategorised card charge that put the books out by its own amount, and a rollup cache of my own that disagreed with the ledger it summarised.

How the engine is derived →

Σ budget-account balances
  = Σ category balances
  + Ready to Assign
  + held for next month
  + Σ future assignments
  − unfunded credit absorbed

The screens

Plain URLs, rendered on the server

No client-side framework and no data stored on the device — every screen is a URL you can open, bookmark or script against.

Start here

Five minutes to a running instance

Everything runs through Docker Compose, and Node is not needed on the host. The seed builds a demo household with a cash overspend, a credit overspend and a card payment already in it, so the screens show real behaviour rather than an empty grid.

Every figure, name and account number in that demo — and in every screenshot on this site — is fictional. 

# a demo household with real behaviour
docker compose --profile seed up seed

# the dev server, auth bypass on
docker compose --profile dev up
