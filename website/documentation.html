Running it

Everything goes through Docker Compose and Node is not needed on the host. The seed builds a demo household that already contains a cash overspend, a credit overspend and a card payment, so the screens show real behaviour instead of an empty grid.

  • One container, one SQLite file on a volume
  • Back that file up and you have backed up everything
  • The dev login bypass refuses to start anywhere production-shaped
# clone, configure, seed
cp .env.example .env
docker compose --profile seed up seed

# development, auth bypass on
docker compose --profile dev up

# tests and typecheck
docker compose --profile test up test

# production
docker compose up -d

One thing must always stay true

Every envelope app has an accounting identity underneath it. Most leave it implicit, which is how a rounding error becomes a bug nobody can reproduce. Here it is written down and asserted after every scenario in the suite — and if a change breaks it, the change is wrong.

  • It caught an uncategorised card charge putting the books out by exactly its own amount — the ordinary state of every imported card row
  • It caught a caching layer that disagreed with the ledger it was summarising

Three rules the documentation follows

Worked examples are tests

Every ₹ figure in the design documents is asserted somewhere in the suite. A number in prose that nothing checks is a number that drifts.

The API reference is tested against the router

A test reads the route table and the router and compares them both ways, so a route cannot ship undocumented and the reference cannot describe something that does not exist.

No real financial data, anywhere

Every household, account, card and figure in the repository is invented, including the sample statement PDFs. Real statements are locked behind a PAN, and neither those nor what they open belong in a repository.
