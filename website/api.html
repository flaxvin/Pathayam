API reference

Every screen is already an endpoint

The app is server-rendered, so there is no second API to keep in sync. A personal token authenticates a script against the same routes your browser uses.

How it works

Authentication

The host in every example below is your own instance — the machine you self-host on, or your hosted subdomain. The public demo at demo.pathayam.app lets anyone in without an account and issues no tokens, so these examples will not run against it.

One header on every request: Authorization: Bearer bgt_…. Tokens are minted in Settings — never while viewing as another member — scoped read or read-write, and shown exactly once. One expires after a whole number of days from 1 to 3650, or never, and stops working the moment its member is removed.

Idempotency

Every write accepts Idempotency-Key. Replaying a key returns the original result instead of acting twice, so a timeout you never saw is safe to retry. The same key with a different body is refused with 422.

Responses

Reads return HTML — this is the same app your browser talks to. /export.json, the CSVs and /healthz return data. Writes redirect on success. Send Accept: application/json and a write answers { "redirect": …, "message": … } instead, an error comes back as { "error": … } with its status, and a request that is not signed in gets 401 rather than a redirect to the sign-in page.

Amounts are rupees in requests and integer paise internally, so nothing is ever stored as a float. Dates are YYYY-MM-DD (or DD-MM-YYYY, the way the app shows them) and months are YYYY-MM, both in IST; a month more than a hundred years from the rest of the budget is refused. Send fields form-encoded, as multipart, or as a flat JSON object — a number or true is read as the text a form would send, and a nested object is ignored.

POST /assign Assign to a category

Set the amount assigned to one category in one month. This is an absolute value, not a delta — sending 4500 makes the assignment 4500, whatever it was before. A month too far back to take an assignment is refused.

Scope

read-write

Parameters

NameTypeDescription
monthstringoptionalYYYY-MM. Defaults to the current month in IST.
category_idstringrequiredThe category receiving the money.
amountnumberoptionalRupees. Accepts an expression such as 450+120. Empty sets it to 0.

Responses

  • 303 — Success. Follow Location to the updated screen.
  • 400 — A field was missing or could not be parsed; the message says which.
  • 401 — No token, or one that is revoked, expired or belongs to a removed member.

  • 404 — An id that does not exist, or names something you cannot see.

Transactions

Where money actually arrives and leaves. Every change here is an event you can undo from Activity.

POST /add Record a transaction

Create one transaction. Money out must name a category — the requirement is enforced on the server, not only in the form. Money in is exempt, because its job is to land in Ready to Assign. A cleared entry dated inside a reconciled period answers with the “Already reconciled” question instead of saving; send it again with confirm_checkpoint=1 to save it and break that checkpoint.

read-write

  • 400 — A field was missing or could not be parsed; the message says which.
  • 401 — No token, or one that is revoked, expired or belongs to a removed member.
  • 403 — A read-only token.
  • 404 — An id that does not exist, or names something you cannot see.
  • 409 — The first request with this Idempotency-Key is still being processed.
  • 422 — Understood and refused; the message says why. Also an Idempotency-Key reused with a different body.

Example

curl -sS -X POST https://pathayam.yourdomain.com/import/undo \
  -H "Authorization: Bearer bgt_…" \
  -H "Idempotency-Key: $(uuidgen)" -d "batch_id=imp_41c"

Writes and the same-origin check

Every write — any method that is not GET, HEAD or OPTIONS — passes one check before it reaches a route, so it covers routes added tomorrow too.

RuleWhat it means
Bearer exemptionA request with Authorization: Bearer … and no session cookie skips the whole check. A browser cannot be tricked into sending one on somebody's behalf, so your scripts need nothing extra. A request that also carries a session cookie is held to the rules below, whatever it says in Authorization.
The hostThe host the request was addressed to must be BASE_URL's hostname, with BASE_URL's port or none — or an IP address or localhost, which no DNS answer can re-point. Anything else is 403: That request was addressed to a different host than BASE_URL. This is what stops DNS rebinding.
Behind a proxyThe host is the Host header, or the right-most X-Forwarded-Host entry when TRUST_PROXY is set. A reverse proxy must pass one of them through, or every write from a browser is refused.
OriginWhen present it must be BASE_URL's origin or the origin the request was addressed by. Anything else is 403: That request came from somewhere else.
RefererWith no Origin, a Referer from one of the same origins will do. Referrer-Policy: same-origin means a same-origin form carries one and a cross-site one does not. With neither header, 403.

A script in a page of the app that uses the session cookie needs no work either: fetch from that page sends a matching Origin on its own.

What a token cannot reach

A deny-list of path prefixes rather than a note in a review checklist. A token that could mint tokens turns one leak into permanent access, and a token that could change the allow-list turns it into somebody else's household.

PrefixWhy it is blocked
/members, /settings/membersThe household allow-list: /members/invite and /members/:id/remove. A token must not change who is allowed in.
/tokensA token must not mint or revoke tokens, including itself.
/impersonateImpersonation is a session-only, logged, human action.
/authSign-in, SSO, and the development bypass state.
/signoutThere is nothing for a token to sign out of.
/settings/passwordA password is a way in that does not need the token, and would outlive revoking it.
/sessionsSigning the member's devices out is a human decision.
/gmail/connect, /gmail/callback, /gmail/disconnectLinking a mailbox changes what can reach the household. /gmail/fetch stays reachable.
