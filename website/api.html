API guide

Every screen is already an endpoint

The app is server-rendered, so there is no separate API to keep in sync — the routes below are the same ones the browser uses. A personal token authenticates a script against them, and a test keeps this page honest by comparing it against the router in both directions.

Getting a token

Minting and using one

Tokens are created from Settings, scoped at creation, and shown exactly once — only a hash is stored, so a lost token is replaced rather than recovered. They are rate-limited separately from browser sessions.

A token carries read or read-write. Nothing else is grantable, and neither scope can reach the routes listed further down. 

# every request, one header
curl -sS https://pathayam.example.com/export.json \
  -H "Authorization: Bearer bgt_…"

# a write needs an idempotency key
curl -sS -X POST https://pathayam.example.com/assign \
  -H "Authorization: Bearer bgt_…" \
  -H "Idempotency-Key: 2026-09-a1b2" \
  -d "month=2026-09&category_id=…&amount=4500"

Guarantees

Two things worth knowing before you script

Idempotency

Retries cannot double-post

Every write accepts an Idempotency-Key. Replaying the same key returns the original result rather than performing the action twice, so a timeout you did not see is safe to retry.

Undo

Everything a token does is reversible

Writes land in the same append-only event log as everything else and undo for thirty days. A script that gets it wrong is a mistake you can walk back, not one you restore a backup for.

Refused

What a token can never reach

A deny-list of path prefixes rather than a note in a review checklist. A token that could mint tokens turns one leak into permanent access, and a token that could change the allow-list turns it into somebody else's household.

PrefixWhy it is blocked
/membersThe household allow-list. A token must not change who is allowed in.
/tokensA token must not mint or revoke tokens, including itself.
/impersonateImpersonation is a session-only, logged, human action.
/authSign-in, SSO, and the development bypass state.
/signoutThere is nothing for a token to sign out of.

Getting everything out

Export is a first-class feature

/export.json returns the complete dataset in an open format — every account, transaction, assignment, lot, loan and event. It is not a summary and not a subset.

Three things are deliberately excluded and asserted absent by tests: the statement identity used to derive PDF passwords, the Gmail refresh token, and anything else that would let an export impersonate you.

Leaving

Self-hosted software should be easy to leave. The database is one SQLite file you can open with any tool, the export is documented and stable, and nothing about the format requires this app to read it.
